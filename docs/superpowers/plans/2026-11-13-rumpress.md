# rumpress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust dual-screen PDF presenter for beamer decks with notes-on-second-screen: beamer shows the slide, notebook shows timer/next-preview/notes/overview.

**Architecture:** One process, two egui viewports (presentation + presenter). A single PDF thread owns the Pdfium document (not thread-safe) and returns rendered RGBA bitmaps; the UI thread holds presentation state and uploads bitmaps as egui textures. Logical slides are derived from PDF page labels (pympress's heuristic).

**Tech Stack:** Rust, eframe/egui (multi-viewport), pdfium-render (dynamic `libpdfium.so`), notify (file watching), clap (CLI).

**Spec:** `docs/superpowers/specs/2026-11-13-rumpress-design.md`

## Global Constraints

- Platform: Arch Linux, Hyprland (Wayland). No X11 code paths.
- Pdfium via `pdfium-render`, loaded dynamically; never AGPL MuPDF.
- All PDF access on one render thread; UI communicates via channels only.
- Notes layout: 2×1 pages split at midpoint; slide left, notes right (`--swap-halves` flips).
- Non-2×1 PDF: full page on both screens + warning banner, never an error.
- Live reload keeps current logical slide when possible (clamp to last).
- Keyboard input centralized: bindings work from either viewport.
- Video and clicker support are out of scope (do not scaffold beyond module boundaries).

## Review Focus

1. **Non-2×1 PDF opened** (aspect ratio not ~2:1): expect full page shown on both screens, warning banner on presenter, no crash, no split. Test in Task 11.
2. **`libpdfium.so` missing**: expect clear error naming the library and the fetch script, non-zero exit. Test in Task 2.
3. **Reload where new PDF has fewer pages** (current page now out of range): expect clamp to last slide, no panic. Test in Task 10.
4. **Keyboard focus on the beamer window**: expect all bindings to work identically. Test in Task 6 (centralized handler unit test).
5. **Only one monitor present**: expect windowed presenter fallback, no panic, message logged. Test in Task 12.
